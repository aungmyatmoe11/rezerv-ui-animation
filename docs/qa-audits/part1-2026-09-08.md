### QA-A11Y-001 — Named `<video>` elements use an invalid `role="img"`

| | |
|---|---|
| **Severity** | medium |
| **Confidence** | 97 |
| **Category** | A11Y |
| **Verifier** | confirmed |
| **Introduced by HEAD** | no (pre-existing) |

**Observed.** `Hero.tsx` sets `role="img"` on the hero `<video>`. `LazyVideo.tsx` sets `role="img"` whenever `alt` is provided.

**Actual.** ARIA in HTML forbids `role="img"` on `<video>`. Live Lighthouse `aria-allowed-role` scores **0** on the hero and other labelled clips. Canvas `role="img"` in `ScrubStage` is valid and is not counted. Decorative clips that set `aria-hidden` omit the role.

**Impact.** Assistive tech may ignore or mishandle names on labelled films. Live accessibility score is pulled down by a disallowed role on the first named media.

**Remediation.** Drop `role="img"` from `<video>`. Keep `aria-label` (or adjacent copy). Leave canvas roles unchanged.

### QA-A11Y-002 — Camera-sensor callout indices fail WCAG AA contrast

| | |
|---|---|
| **Severity** | medium |
| **Confidence** | 97 |
| **Category** | A11Y |
| **Verifier** | confirmed |
| **Introduced by HEAD** | no (pre-existing) |

**Observed.** `.calloutIndex` uses `--cherry-hi` (`#71405b`) on a near-black chip. Live mobile Lighthouse: **2.5:1** at 11px / 8.3pt, expected **4.5:1**. Independent WCAG math on `#71405b` vs `#050507` is **2.506:1**.

**Actual.** Lab contrast hits on `--bone-faint` `#55534f` are **stale**. Current `--bone-faint` is `#8a8780` (~5.8:1 on black). Body copy on the same chip uses `--bone` and passes. Desktop lab missed the indices because they sit at opacity 0 while pinned. The 01–05 numbers remain readable-size text below AA.

**Impact.** Low-vision users cannot reliably read the sensor legend indices, especially on the mobile stacked video-tier layout.

**Remediation.** Color indices with `--bone`, `--bone-dim`, or `--c-high`, or lighten `--cherry-hi` only on those numbers.

### QA-PERF-001 — Hero poster preload omits `?v=MEDIA_REV`

| | |
|---|---|
| **Severity** | medium |
| **Confidence** | 96 |
| **Category** | PERF |
| **Verifier** | confirmed |
| **Introduced by HEAD** | yes (`posterSrc` / `videoSrc` / `framePath` gained the query; the layout preload did not) |

**Observed.** `src/app/layout.tsx` declares `<link rel="preload" as="image" href="/poster/hero.jpg">`. `posterSrc('hero')` (used by `<video poster>` and `useHeroPreload`) is `/poster/hero.jpg?v=${MEDIA_REV}` (`d2560b` at HEAD). Metadata icons also point at the unversioned JPEG.

**Actual.** `/poster` is served `immutable` (`max-age=31536000`). After a `MEDIA_REV` bump the HTML preload and the element's poster are different URLs: the browser can fetch twice, and a returning tab can keep the old LCP still from the immutable cache while the film URL is new.

**Impact.** Duplicate LCP request on first view; stale hero poster after asset regeneration.

**Remediation.** Point the preload (and icons) at `posterSrc('hero')` so every poster URL shares the cache-bust query.

### QA-A11Y-003 — Reduced-motion still waits on the 4K hero film

| | |
|---|---|
| **Severity** | medium |
| **Confidence** | 92 |
| **Category** | A11Y |
| **Verifier** | confirmed |
| **Introduced by HEAD** | no (pre-existing) |

**Observed.** `prefers-reduced-motion` maps to the `static` tier: no pin, no scrub, `canAutoplay: false`. Hero playback then pauses on the poster. `LazyVideo` correctly skips promoting `preload` when `!canAutoplay`.

**Actual.** The hero `<video>` always sets `preload="auto"`. `useHeroPreload` has no policy guard: it still listens for `canplaythrough` / `readyState >= 3` and drives the preloader from the 3840×2160 film (`CLIP_SIZE.hero`). Static tier skips *playback*, not *fetch*. Other clips do not wait on bytes.

**Impact.** Visitors who asked for less motion still sit on the loading curtain until the 4K hero buffers (or the 8s cap). That is the opposite of the reduced-motion bonus the Part 1 rubric awards.

**Remediation.** On the static tier, `setReady()` from the poster and keep `preload="none"` (or skip attaching the film) so the curtain does not wait on the 4K download.

### QA-CORRECTNESS-002 — UltraTransition leaves inline opacity/transform after teardown

| | |
|---|---|
| **Severity** | low |
| **Confidence** | 90 |
| **Category** | CORRECTNESS |
| **Verifier** | confirmed |
| **Introduced by HEAD** | no (pre-existing) |

**Observed.** `UltraTransition` `onUpdate` writes `card.style.opacity` and `card.style.transform` (0.3→1 and scale 0.94→1). Cleanup only resets `willChange` and `kill()`s the trigger. `animation` is `undefined`, so GSAP does not revert those properties. CSS rest state is `opacity: 1` with no transform.

**Actual.** If `canPin` flips mid-ramp (resize across 768 / reduced-motion), the last inline values stick. A card stopped at progress 0 stays at 0.3 opacity and 0.94 scale even though the static/mobile contract is the calm full-opacity end state.

**Impact.** The only bright clip on the page can remain dimmed and undersized after a tier change.

**Remediation.** Clear `opacity` / `transform` (or `clearProps`) on teardown, and set the rest state when `!canPin`.

### QA-CORRECTNESS-003 — Failed frame load drops the pin and jumps document height

| | |
|---|---|
| **Severity** | low |
| **Confidence** | 88 |
| **Category** | CORRECTNESS |
| **Verifier** | confirmed |
| **Introduced by HEAD** | no (pre-existing) |

**Observed.** `useScrubSequence` comments that the pin is created **on mount** so document height stays constant (historical jumps of 1,620–2,520 px per section). `failed` is in the `useGSAP` dependency list: a failed fetch skips pin creation and kills an existing pin. All eight scrub sections pass `videoLayout="stacked"`, so `mode === 'video'` switches to the stacked looping-video layout. `loadFrames` / `loadOne` reject the **whole** set if any JPEG 404s.

**Actual.** Happy-path height tests do not cover a missing frame. One broken JPEG therefore collapses that section's pin spacer. Bounded uncertainty: not reproduced with a live 404 this run; the path is forced by the hook and `ScrubStage` layout switch.

**Impact.** A CDN miss or a drifted `FRAME_COUNTS` value drops document height while the visitor is on the page, which is the exact class of jump the pin-on-mount comment was written to prevent.

**Remediation.** Keep the spacer (or an overlay fallback) so height stays constant; do not pin the stacked box. Fail a single JPEG without rejecting the entire sequence if a partial set can still paint.
